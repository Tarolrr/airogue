# План: продолжить исправление CI-тестов

- Задача: [Tarolrr/airogue#7 — CI, тесты #2](https://github.com/Tarolrr/airogue/issues/7).
- Базовая ветка: `main`.
- Этот PR содержит только спецификацию; реализация относится к следующей итерации.

## Проблема

Предыдущая итерация добавила workflow, offline-изоляцию, CLI check и headless smoke-test игрового цикла. На текущем `main` job `lint` проходит, но `tests` для `2ec468e` падает после успешной установки зависимостей; из-за этого шаг CLI не запускается. У issue нет комментариев. Hosting API показал статус шагов, но отклонил чтение текста job log (HTTP 415), поэтому конкретный baseline должен быть заново зафиксирован на Python 3.10, а не выведен из догадки.

Исходники показывают независимые причины нестабильности:

- `tests/test_theme_generator.py` возвращает словарь из mock chain напрямую, обходя `SelectRandomThemeParser`, но ожидает результат parser и вызов `random.choice`.
- `tests/test_world_generation_isolation.py` патчит отсутствующий `llm.world.ChatOpenAI`; фактическая точка создания клиента — `llm.generators.base.ChatOpenAI`. Некорректная подмена смешивает проверку делегирования с требованием API key.
- Тесты `new_world()` пытаются провести JSON через незавершённый ECS-контракт: `game/world_tools.py` ожидает `signals` и `slots`, которых нет в `ComponentModel`. Это не поддерживаемая интеграция, которую нельзя объявлять рабочей mock-ом.
- Общие фикстуры ещё содержат старую схему `Item` (`symbol`, `properties`) и импорт отсутствующего `utils.validation`.

Локальный baseline не получен: доступен Python 3.13.5, а locked `pydantic-core==2.16.3` не имеет подходящего wheel и его сборка прервалась из-за отсутствующего `cc`. Это ограничение планирующего окружения, не состояние CI: GitHub Actions использует Python 3.10 и зависимости установил.

## Цели и границы

1. Сделать существующий offline-набор содержательно проходящим на Python 3.10 и Poetry 1.8.2.
2. Исправить тестовые данные и моки по фактическим контрактам, без OpenAI, сети и дисплея.
3. Отделить валидность `WorldModel` от пока неготовой загрузки LLM JSON в ECS.
4. Довести job `tests` до CLI help, coverage и JUnit, сохранив текущий CI.

Вне задачи: реализация `signals`/`slots`, путь «LLM JSON → playable ECS world», live-LLM CI, обновление зависимостей/lock-файла, новый фреймворк тестов и массовое форматирование. Не использовать `skip`, `xfail`, `continue-on-error` или широкие исключения для сокрытия failures.

## Подход

### 1. Зафиксировать Python-3.10 baseline

На чистом Poetry environment выполнить те же команды, что применяет workflow, без ключа. Записать исходные failures/errors/skips и сопоставить с JUnit/artifact или доступным job log. Если hosted log остаётся недоступным, отметить это, а не считать пустой ответ успешным. Не менять lock-файл ради Python 3.13.

Сохранить исключение `tests/test_world_generator_e2e.py` из CI, opt-in `--run-requires-openai-api` и socket-блокировку default suite. Фиктивный API key не должен разрешать сеть.

### 2. Исправить unit-тесты и общие фикстуры

Привести фикстуры `tests/conftest.py` к текущему `Item(name, ascii_symbol, description)`. Удалить или заменить ссылку на отсутствующий `utils.validation`, не создавая несуществующий production-модуль ради старой фикстуры.

Переписать проверки `ThemeGenerator` на реальное наблюдаемое поведение:

- для `generate_single()` подменить LLM/runnable и проверить stripped результат;
- передать `SelectRandomThemeParser` валидный JSON и проверить извлечение `themes` и выбор из списка;
- для `generate()` собрать stub chain, который действительно проходит через parser, либо заменить parser на экземпляре.

Патчить `llm.generators.base.ChatOpenAI` до создания `World` или специализированного генератора. Проверки `World` должны проверять делегирование theme/title/plot/mechanics/items/complete model. Проверку отсутствующего ключа оставить отдельной — с очищенным окружением и без mock клиента.

### 3. Сделать model и loader-тесты честными

Сохранить содержательные проверки реальных Pydantic-моделей: валидный/неполный JSON, malformed JSON, `Items` и минимальная `WorldModel`. Заменить `assert result is not None`, пустые `pass` и tautological assertions на конкретные поля, вызовы и исключения.

Убрать либо заменить дублирующие тесты `new_world()`, которые обещают успешный `Game` без `signals`/`slots`. Это не должны быть новые skips: ограничение нужно отразить в `tests/README.md`. Headless coverage входа остаётся в `tests/test_game_startup.py`, где loader честно заменён настоящим тестовым Registry. Проверки `FileNotFoundError`/malformed JSON сохранять у `new_world()` лишь если они проходят реальный путь до ECS-контракта и не создают LLM; иначе выделение функции чтения — отдельная задача.

Также обработать четыре безусловных `pytest.skip(...)` в `tests/test_integration.py`: каждый placeholder либо заменить поддерживаемым наблюдаемым сценарием, либо удалить вместе с неподдерживаемым контрактом и явно описать это ограничение в `tests/README.md`. После этого составить inventory пропусков: в нём должны остаться только намеренные условные skips с причиной, включая opt-in `requires_openai_api`; постоянные заглушки не должны считаться успешным offline-набором.

### 4. Подтвердить CI и документацию

Не менять triggers, pinned actions, Python 3.10, coverage/JUnit либо узкий lint workflow, если baseline не обнаружит ошибку именно там. Исправленный suite должен позволить выполнить `python -m llm.generators.cli --help` без генерации мира и сети.

Обновить `tests/README.md` (README — только при изменении команды): offline-suite проверяет модели, mock-based генераторы и headless loop, но не поддержку `new_world()` для сериализованного LLM мира. После штатного Looper push проверить `tests` и `lint` для нового SHA и artifacts при success/failure; не считать старый success lint доказательством исправления.

## Риски

| Риск | Мера |
| --- | --- |
| Старый lock не ставится на локальном Python 3.13 | Валидировать на CI/локальном Python 3.10, не обновлять стек в этой задаче. |
| Mock создаёт настоящий клиент | Патчить фактический импорт до конструктора, сохранить socket-block; key-test не мокировать. |
| Чистка loader-тестов уменьшает покрытие | Сохранить реальные model/JSON и startup проверки, явно описать неполный ECS контракт. |
| Parser-test снова тестирует только MagicMock | Использовать валидный JSON и настоящий parser/явную подмену parser instance. |
| CI падает раньше artifact/CLI | Проверить steps и generated coverage.xml/test-results.xml на новом SHA. |

## Валидация и критерии приёмки

- [ ] Baseline на Python 3.10 задокументирован отдельно от исправленного результата.
- [ ] Полный offline-suite проходит без ключа, сети, дисплея и `world_model.json`; socket regression остаётся красной при попытке соединения.
- [ ] Theme parser и `World` wrapper используют действующие точки mock-ирования; общие фикстуры соответствуют Pydantic-схемам.
- [ ] Model/JSON проверки содержательны; неполный ECS loader не скрыт skip/xfail и отражён в документации.
- [ ] Каждый из четырёх прежних безусловных integration placeholders заменён наблюдаемой поддерживаемой проверкой либо удалён с документированным в `tests/README.md` неподдерживаемым контрактом; финальный inventory содержит только намеренные условные skips и их причины.
- [ ] `tests`, CLI help, coverage/JUnit и существующий lint проходят на Python 3.10 и на новом GitHub Actions SHA.
- [ ] `git diff --check` проходит; нет секретов, generated worlds, lockfile churn или несвязанных игровых правок.

Целевые команды реализации:

```bash
poetry env use python3.10
poetry install --no-root
poetry run python -m pytest tests/ -v --ignore=tests/test_world_generator_e2e.py --cov=main --cov=game --cov=llm --cov-report=term-missing --cov-report=xml --junitxml=test-results.xml
poetry run python -m llm.generators.cli --help
poetry run flake8 . --select=E9,F63,F7,F82 --exclude=.git,.venv,scratch.py,game/pipeline.py,game/slots.py,llm/models.py
git diff --check
```

## Проверка этой спецификации

Прочитаны README, `docs/INITIAL_REVIEW.md`, workflow, тесты, генераторы, модели, `game/world_tools.py`, предыдущая спецификация #4 и последующая история. Проверены issue #7 и отсутствие комментариев. Trusted hosting CLI подтвердил: на `2ec468e` зависимости в CI установились, `lint` success, `tests` failed до CLI help; доступные job metadata не содержат pytest output, а log endpoint вернул HTTP 415. Локальная последовательная установка блокирована Python 3.13/старым `pydantic-core` и отсутствием C linker. Runtime-код, зависимости и workflow этой спецификацией не менялись.
