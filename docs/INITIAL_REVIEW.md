## Ограничения реализации, влияющие на инструкции

1. **Игровой старт не воспроизводится из чистого checkout.** `game/world_tools.py:new_world()` читает отсутствующий `world_model.json`. Даже JSON от `WorldGenerator.generate()` не решает проблему: `global_entities` остаётся пустым, а загрузчик ожидает `Game`, `signals` и `slots`, которых нет в схеме `ComponentModel`.
2. **Ленивая инициализация не означает отсутствие требования ключа.** `BaseGenerator` создаёт клиент при доступе к `.llm`, но `World.__init__` сразу обращается к этому свойству для вывода в консоль.
3. **Контракт предметов расходится.** `WorldGenerator.generate_items()` использует `item['symbol']`, тогда как `Item` требует `ascii_symbol`. Не обещать успешное выполнение всей цепочки без согласования данных.
4. **Тесты не дают гарантированного baseline.** Есть `assert True`, пропущенные интеграционные сценарии и моки удалённых путей. Hooks для API-тестов размещены в обычном тестовом модуле. Требуется отдельная задача на изоляцию сети и реальные проверки поведения.
5. **Зависимости требуют воспроизводимой проверки.** Lock-файл создан Poetry 1.8.2, проект допускает Python `^3.10`. Импортируемые напрямую `pydantic` и `dotenv` не объявлены прямыми зависимостями. Не обновлять версии в рамках документационного ревью.

## Приоритеты следующих задач

2. Согласовать схему мира и загрузчик ECS; добавить минимальную фикстуру мира и тест загрузки без LLM, затем проверить графический запуск вручную.
3. Согласовать интерфейсы генераторов и схемы предметов с тестами, обновить `MODULE_CONTRACTS.md` и `ARCHITECTURE.md` по фактическому поведению.
4. После стабильной основы пересмотреть roadmap и реализовать обработку ошибок, компоненты и пайплайны. Сейчас `GeneratorPipeline.run()` явно вызывает `NotImplementedError`.
